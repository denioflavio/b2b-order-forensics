Home is a welcome/purchasing page, not a KPI dashboard. Orders is a bounded list of
the authenticated buyer's ACME purchases. No edit/delete of persisted orders.
Page20 renders eight true catalog cards and an adjacent cart. Search/category are
client filters of the rendered eight products. Page30 reviews the durable order,
not live catalog prices. Page50 shows commercial status, immutable line prices and
sibling order references. Use native Dynamic Content with custom HTML by explicit
user request, not a static-data substitute for a native report.

## Behavior and validation
Page20 Initialize Cart runs before header. SHOP_CART on-demand handles READ, ADD,
SET only. Product and quantity numeric and validated by the package; ignored client
prices. JSON response carries current lines and server totals, rendered using textContent.
Inline trash asks contextual confirmation; quantity changes refresh cart only.
CHECKOUT native submit calls begin_checkout and redirects to30.
Page30 PLACE_ORDER processes first attempt. If WAIT_RETRY, redirect to30; a retry
indicator triggers RETRY_ORDER as a separate HTTP POST. That POST calls prepare_retry
then place_order through the same API. No clone and no order creation during GET.
Successful processing redirects to50. Native APEX exception propagation remains.
A confirmation GET never calls the processing API; repeated DONE is a no-op.
No generic exception message fabricates an ORA code. Buyer sees the reference before
submission and can send a screenshot to support.

## UI, accessibility and static assets
Light background, dark ink, blue primary actions, rounded white cards, restrained
borders, local SVG product illustrations. Desktop grid/cart split; mobile single column.
Keyboard-operable search, category buttons, add/remove/quantity and checkout.
Explicit labels, alt/aria text, live status, disabled controls during AJAX, server error
message via APEX notifications. Empty cart and no-orders have useful purchase links.
CSS and JS are in APEXLang page fields. SVG source assets are local and embedded as
data URLs in CSS, with whitelist artwork_key mapping; no external assets/dependencies.
No technical labels, sessions, hashes, correlations, internal service/account values.
